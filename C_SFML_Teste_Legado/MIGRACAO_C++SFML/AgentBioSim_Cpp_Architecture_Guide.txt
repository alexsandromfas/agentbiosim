AGENTBIOSIM CPP ARCHITECTURE GUIDE
===================================

Documento de referência para orientar o Codex na migração do AgentBioSim de Python/Pygame/PyQt6 para C++/SFML/CMake.

Este documento NÃO deve ser tratado como uma tradução literal dos arquivos Python. Ele define a arquitetura-alvo da nova versão C++.

Objetivo geral
--------------
Migrar o AgentBioSim para C++/SFML/CMake preservando 100% das funcionalidades, parâmetros, menus, modos de simulação, modos de visão, modelos neurais, ferramentas de UI, persistência, diagnóstico e fluxos de uso existentes.

A migração deve melhorar a arquitetura, desempenho e manutenibilidade. O objetivo não é copiar a estrutura de arquivos Python, mas preservar responsabilidades, comportamentos e parâmetros.

Regra central
-------------
Não preserve a estrutura dos arquivos Python. Preserve as responsabilidades, os parâmetros, os comportamentos e os fluxos de uso.

A nova arquitetura deve ser pensada como um simulador científico modular, não como um protótipo visual.

Princípios arquiteturais
------------------------
1. Engine headless
   O motor da simulação não deve depender da UI nem do renderizador.
   Ele deve poder rodar em modo headless para benchmarks, experimentos longos e testes automatizados.

2. Separação clara de responsabilidades
   Simulação, percepção, redes neurais, sistemas, renderização, UI, persistência e diagnóstico devem ser módulos separados.

3. Parâmetros como fonte única de verdade
   Todos os parâmetros devem estar registrados em um ParameterRegistry tipado.
   A UI deve ler esse registro para criar ou validar controles.
   Nenhum parâmetro deve ficar solto em código.

4. Visão orientada a desempenho
   O gargalo principal do projeto é a visão dos agentes.
   A percepção deve ser feita com estruturas orientadas a dados, arrays contíguos, spatial hash, snapshots e buffers reutilizáveis.

5. Arquitetura híbrida
   Use objetos para organização de alto nível.
   Use estrutura orientada a dados para processamento pesado, especialmente agentes, visão, colisão, interação e redes neurais em lote.

6. UI modular
   A UI não deve ficar em um único arquivo gigante.
   Dividir a UI em painéis, menus, toolbars, inspetores e viewers.

7. Persistência com schema
   Save/load deve ter versão de schema e documentação clara.
   Deve salvar parâmetros, mundo, agentes, comida, obstáculos, labels, cérebros, RNG e protótipos.

8. Diagnóstico desde o início
   Profiler, métricas, logs e benchmarks não devem ser adicionados apenas no final.
   Eles devem acompanhar a migração.

9. Migração incremental
   Cada etapa deve compilar e rodar.
   O Codex não deve avançar para etapas futuras sem autorização explícita.

10. Preservação funcional
   Se qualquer funcionalidade, menu, controle ou parâmetro ainda não for portado, registrar em arquivo de pendências.

Arquitetura geral
-----------------
Camadas principais:

1. Core / Simulation
   A verdade da simulação. Não conhece UI.

2. Presentation / Render / UI
   Mostra e controla, mas não decide regra biológica.

3. Tools / Persistence / Diagnostics
   Salva, mede, depura, exporta e importa.

Fluxo ideal:

App
  - processa eventos SFML
  - atualiza UI ImGui
  - envia comandos para Engine
  - chama Engine.update(dt)
  - chama Renderer.draw(state)
  - chama UI.draw()

Engine
  - processa comandos
  - executa pipeline de sistemas
  - atualiza estado da simulação
  - expõe uma view somente leitura para UI e render

Renderer
  - desenha estado da simulação
  - não altera regras da simulação

UI
  - envia comandos
  - altera parâmetros via ParameterRegistry
  - lê snapshots/estado somente leitura

Arquivos sugeridos:

├─ App.hpp
├─ App.cpp
└─ main.cpp

Responsabilidades:
- criar janela SFML
- inicializar Engine
- inicializar Renderer
- inicializar UI
- controlar loop principal
- processar eventos globais
- coordenar update/render
- não implementar regra de simulação diretamente

Fluxo recomendado:

while window is open:

    ui.handleEvent(event)
    engine.dispatch(commands from UI/input)
    engine.update(real_dt)
    renderer.draw(engine.view())
    ui.draw(engine.view())
    window.display()

Modos obrigatórios:

- aproximação rápida por centroide do objeto

- modo principal de alto desempenho

- evita interseção por raio quando possível

fullbody:
- raycast geométrico
- usa ray_circle_intersect

- retina_bins_mode: nearest, strongest, sum_saturating, weighted_average
- retina_bins_distance_subdivisions
- retina_bins_distance_distribution: linear, near_detail
- retina_bins_distance_falloff: linear, quadratic, step, none
- retina_bins_projection: center, center_edges, apparent_size
- retina_bins_candidate_limit
- retina_bins_obstacles_block_vision

Regra de desempenho:
Evitar alocação dentro do loop de percepção.
Usar SpatialSnapshot e VisionBuffers.
Agrupar agentes com mesma configuração visual.

Regras para prompts ao Codex
============================

Sempre incluir estas regras em tarefas de migração:

1. Execute somente a etapa solicitada.
2. Não avance para etapas futuras sem autorização.
3. O projeto deve compilar ao final da etapa.
4. Atualize documentos de status.
5. Não remova parâmetros.
6. Não remova funcionalidades.
7. Se algo ficar pendente, registre explicitamente.
8. Não faça tradução literal Python -> C++.
9. Preserve comportamento e fluxos de uso.
10. Prefira arquitetura C++ idiomática, modular e performática.

Critérios de sucesso da arquitetura
===================================

A arquitetura será considerada correta se:

1. O Engine roda sem UI.
2. A UI é modular.
3. Todos os parâmetros atuais existem no ParameterRegistry.
4. A visão pode ser otimizada sem mexer na UI.
5. O renderizador não altera simulação.
6. Save/load preserva estado completo.
7. Benchmarks podem rodar em modo headless.
8. A simulação consegue evoluir para milhares de agentes.
9. A implementação permite novos modelos neurais, incluindo RNN e futuramente NEAT.
10. Nenhuma funcionalidade atual some silenciosamente.

Prioridade de otimização
========================

1. Visão dos agentes
2. Spatial hash / spatial snapshot
3. Forward neural em lote
4. Interação comida/agente/predador
5. Locomoção e energia
6. Renderização
7. UI

Observações finais para o Codex
===============================

Este documento é a arquitetura-alvo.
Não usar a estrutura Python como estrutura final.
Usar os arquivos Python como fonte de funcionalidades, parâmetros e comportamento.

A nova versão C++ deve ser melhor organizada, mais performática e mais fácil de expandir.

Foco principal:
- preservar tudo que já existe;
- melhorar arquitetura;
- resolver gargalo de visão;
- permitir experimentos científicos;
- permitir UI rica sem virar um arquivo gigante;
- permitir migração incremental segura.

Frase-guia:

Primeiro garanta paridade. Depois otimize. Depois refine a UI.
